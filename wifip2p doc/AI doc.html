一、概述与方案设计前提

Wi-Fi P2P（也被称为 Wi-Fi Direct）允许具备相应硬件支持的 Android 设备通过点对点直连技术进行高速数据通信，而无需依赖任何中间局域网无线路由。针对开源项目 leavesCZY/WifiP2P 的设计架构，本文档将其传统的基于 BroadcastReceiver 回调、异步 Listener 嵌套以及传统 Java Socket 的阻塞式 I/O 逻辑，全面重隔升级为基于 Kotlin 协程（Coroutines）与挂起函数（Suspend Functions） 的现代化线性架构。该方案能够彻底消除深度回调地狱，在上层提供顺序直观、健壮性极强的 API，完美支持高可靠性的文件夹/文件流传输，并配备实时的速度与进度双向反馈体系。

1.1 环境前提与权限声明

要成功启动 Wi-Fi P2P 功能，Android 客户端设备必须在 AndroidManifest.xml 中声明以下完整的静态权限。依据 Android 系统的最新安全模型（特别是 API 33+），位置权限与附近的设备扫描权限属于运行时强校验权限，必须在运行时引导用户授予：

<!-- 基础网络状态与 Wi-Fi 硬件控制权限 -->
<uses-permission android:name="android.permission.ACCESS_WIFI_STATE" />
<uses-permission android:name="android.permission.CHANGE_WIFI_STATE" />
<uses-permission android:name="android.permission.CHANGE_NETWORK_STATE" />
<uses-permission android:name="android.permission.INTERNET" />
<uses-permission android:name="android.permission.ACCESS_NETWORK_STATE" />

<!-- Android 13 以前发现设备需要精确地理位置权限 -->
<uses-permission android:name="android.permission.ACCESS_FINE_LOCATION" />

<!-- Android 13 (API 33) 及以上所需附近设备发现权限 -->
<uses-permission android:name="android.permission.NEARBY_WIFI_DEVICES" 
                 android:usesPermissionFlags="neverForLocation" />

1.2 运行时状态与权限级联校验

在发起任何 P2P 扫描或建立连接操作前，必须按顺序执行严格的组合级联校验：检查底层硬核 Wi-Fi 开关状态、定位服务开关、系统版本特定的运行时权限。以下为框架层封装的统一挂起检查函数：

import android.content.Context
import android.content.pm.PackageManager
import android.net.wifi.WifiManager
import android.location.LocationManager
import android.os.Build
import androidx.core.content.ContextCompat
import kotlinx.coroutines.Dispatchers
import kotlinx.coroutines.withContext

sealed class ValidateResult {
    object Success : ValidateResult()
    data class Failure(val reason: String) : ValidateResult()
}

suspend fun verifyP2PEnvironment(context: Context): ValidateResult = withContext(Dispatchers.Default) {
    // 1. 检查物理 Wi-Fi 是否开启
    val wifiManager = context.applicationContext.getSystemService(Context.WIFI_SERVICE) as? WifiManager
    if (wifiManager == null || !wifiManager.isWifiEnabled) {
        return@withContext ValidateResult.Failure("ERROR_WIFI_DISABLED: 请先开启设备的Wi-Fi硬件开关。")
    }

    // 2. 运行时权限动态校验
    if (Build.VERSION.SDK_INT >= Build.VERSION_CODES.TIRAMISU) {
        if (ContextCompat.checkSelfPermission(context, android.Manifest.permission.NEARBY_WIFI_DEVICES) 
            != PackageManager.PERMISSION_GRANTED) {
            return@withContext ValidateResult.Failure("ERROR_PERMISSION_DENIED: 缺少 NEARBY_WIFI_DEVICES 权限。")
        }
    } else {
        if (ContextCompat.checkSelfPermission(context, android.Manifest.permission.ACCESS_FINE_LOCATION) 
            != PackageManager.PERMISSION_GRANTED) {
            return@withContext ValidateResult.Failure("ERROR_PERMISSION_DENIED: 缺少 ACCESS_FINE_LOCATION 权限。")
        }
        // Android 13 以下部分厂商强制要求开启定位服务才能扫描 P2P 节点
        val locationManager = context.getSystemService(Context.LOCATION_SERVICE) as? LocationManager
        val isGpsEnabled = locationManager?.isProviderEnabled(LocationManager.GPS_PROVIDER) == true
        val isNetworkEnabled = locationManager?.isProviderEnabled(LocationManager.NETWORK_PROVIDER) == true
        if (!isGpsEnabled && !isNetworkEnabled) {
            return@withContext ValidateResult.Failure("ERROR_LOCATION_DISABLED: 必须开启系统定位服务才能发现附近 P2P 设备。")
        }
    }
    return@withContext ValidateResult.Success
}

二、Wi-Fi P2P 全生命周期状态模型与拓扑演进

Android 系统内置的 Wi-Fi P2P 状态完全由不可控的系统级广播进行驱动。为了完成无缝接入，框架层将其统一收拢至 StateFlow 中进行统一建模。

2.1 系统四大核心广播状态映射

系统原始广播 Action 框架映射状态 业务核心含义
WIFI_P2P_STATE_CHANGED_ACTION P2pStatus.Enabled / Disabled 表明当前设备的 Wi-Fi P2P 硬件功能是否可用。
WIFI_P2P_PEERS_CHANGED_ACTION 触发 requestPeers() 附近可用的对等节点设备列表发生增减变动。
WIFI_P2P_CONNECTION_CHANGED_ACTION P2pStatus.Connected / Disconnected 连接状态骤变，可提取出当前是群主(GO)还是组员(GC)，并能获取群主IP。
WIFI_P2P_THIS_DEVICE_CHANGED_ACTION 更新本机配置缓存 本机的设备网络信息（如MAC地址、设备名、持久化角色）发生变化。
核心闭坑指南：MAC地址隐藏保护

自 Android 10+ 起，出于用户隐私和防追踪保护，系统在广播返回的 WifiP2pDevice 结构体中，会将本地及远端对等节点的 deviceAddress（MAC地址）字段部分抹除或重置为随机伪造 MAC。因此，框架层严禁依赖该 MAC 地址做持久化唯一标识。推荐在握手阶段由 TCP Socket 通道自传生成的 UUID 作为逻辑对端节点的唯一 Key。

三、基于状态机与协程的底层通道 management

为了将完全异步的 WifiP2pManager 体系线性化，我们使用 suspendCancellableCoroutine 挂起函数对底层回调进行高阶封装。

3.1 全局连接状态抽象模型封装

import android.net.wifi.p2p.WifiP2pDevice
import android.net.wifi.p2p.WifiP2pInfo

sealed class P2pConnectionState {
    object Idle : P2pConnectionState()
    object Discovering : P2pConnectionState()
    data class PeersAvailable(val devices: List<WifiP2pDevice>) : P2pConnectionState()
    data class Connecting(val target: WifiP2pDevice) : P2pConnectionState()

3.2 底层回调的线性挂起转换层（核心实现）

import android.annotation.SuppressLint
import android.net.wifi.p2p.WifiP2pConfig
import android.net.wifi.p2p.WifiP2pManager
import android.net.wifi.p2p.WifiP2pManager.ActionListener
import java.lang.RuntimeException
import kotlin.coroutines.resume
import kotlin.coroutines.resumeWithException
import kotlinx.coroutines.suspendCancellableCoroutine

class CoroutineP2pManager(
    private val manager: WifiP2pManager,
    private val channel: WifiP2pManager.Channel
) {

    @SuppressLint("MissingPermission")
    suspend fun discoverPeersSuspend(): Boolean = suspendCancellableCoroutine { continuation ->
        manager.discoverPeers(channel, object : ActionListener {
            override fun onSuccess() {
                // 仅代表启动扫描动作成功，不代表已经扫描到数据
                if (continuation.isActive) continuation.resume(true)
            }

            override fun onFailure(reason: Int) {
                if (continuation.isActive) {
                    continuation.resumeWithException(RuntimeException("启动设备发现失败，错误码: $reason"))
                }
            }
        })
    }

    @SuppressLint("MissingPermission")
    suspend fun connectSuspend(config: WifiP2pConfig): Boolean = suspendCancellableCoroutine { continuation ->
        manager.connect(channel, config, object : ActionListener {
            override fun onSuccess() {
                if (continuation.isActive) continuation.resume(true)
            }

            override fun onFailure(reason: Int) {
                if (continuation.isActive) {
                    continuation.resumeWithException(RuntimeException("建立 P2P 物理连接失败，错误码: $reason"))
                }
            }
        })
    }

    suspend fun stopPeerDiscoverySuspend(): Boolean = suspendCancellableCoroutine { continuation ->
        manager.stopPeerDiscovery(channel, object : ActionListener {
            override fun onSuccess() {
                if (continuation.isActive) continuation.resume(true)
            }

            override fun onFailure(reason: Int) {
                if (continuation.isActive) {
                    continuation.resume(false)
                }
            }
        })
    }

    suspend fun disconnectSuspend(): Boolean = suspendCancellableCoroutine { continuation ->
        manager.removeGroup(channel, object : ActionListener {
            override fun onSuccess() {
                if (continuation.isActive) continuation.resume(true)
            }

            override fun onFailure(reason: Int) {
                if (continuation.isActive) {
                    // 部分场景没有群组时会返回错误码 2（BUSY），此时判定为已经处于断开状态
                    if (reason == WifiP2pManager.BUSY) {
                        continuation.resume(true)
                    } else {
                        continuation.resumeWithException(RuntimeException("移除 P2P 群组失败，错误码: $reason"))
                    }
                }
            }
        })
    }
}

3.3 状态监听器与重连补偿机制设计

通过组合 BroadcastReceiver 并将底层事件派发至上层 MutableStateFlow，可实现全自动状态变化监听。针对移动端经常发生的因距离过远、瞬时干扰导致的物理链路意外断连，框架设计了带有最大尝试次数的重连补偿算法：

import android.content.BroadcastReceiver
import android.content.Intent
import android.net.NetworkInfo
import android.net.wifi.p2p.WifiP2pManager.PeerListListener
import kotlinx.coroutines.flow.MutableStateFlow
import kotlinx.coroutines.flow.asStateFlow
import kotlinx.coroutines.CoroutineScope
import kotlinx.coroutines.launch
import kotlinx.coroutines.delay

class WifiP2pStateMediator(
    private val p2pManager: CoroutineP2pManager,
    private val nativeManager: WifiP2pManager,
    private val channel: WifiP2pManager.Channel,
    private val scope: CoroutineScope
) {
    private val _connectionState = MutableStateFlow<P2pConnectionState>(P2pConnectionState.Idle)
    val connectionState = _connectionState.asStateFlow()

    private var lastConfig: WifiP2pConfig? = null
    private var reconnectCount = 0
    private const val MAX_RECONNECT_ATTEMPTS = 3

    fun createReceiver(): BroadcastReceiver = object : BroadcastReceiver() {
        @SuppressLint("MissingPermission")
        override fun onReceive(context: Context, intent: Intent) {
            when (intent.action) {
                WifiP2pManager.WIFI_P2P_PEERS_CHANGED_ACTION -> {
                    nativeManager.requestPeers(channel) { peerList ->
                        _connectionState.value = P2pConnectionState.PeersAvailable(peerList.deviceList.toList())
                    }
                }
                WifiP2pManager.WIFI_P2P_CONNECTION_CHANGED_ACTION -> {
                    val networkInfo = intent.getParcelableExtra<NetworkInfo>(WifiP2pManager.EXTRA_NETWORK_INFO)
                    val wifiP2pInfo = intent.getParcelableExtra<WifiP2pInfo>(WifiP2pManager.EXTRA_WIFI_P2P_INFO)
                    
                    if (networkInfo?.isConnected == true && wifiP2pInfo != null) {
                        reconnectCount = 0 // 成功连接，重置计数器
                        _connectionState.value = P2pConnectionState.Connected(wifiP2pInfo)
                    } else {
                        val previous = _connectionState.value
                        _connectionState.value = P2pConnectionState.Disconnected("物理链路已断开")
                        if (previous is P2pConnectionState.Connected) {
                            handleAutoReconnect()
                        }
                    }
                }
            }
        }
    }

    fun setConnectConfig(config: WifiP2pConfig) {
        this.lastConfig = config
    }

    private fun handleAutoReconnect() {
        val config = lastConfig ?: return
        if (reconnectCount < MAX_RECONNECT_ATTEMPTS) {
            scope.launch {
                reconnectCount++
                delay(3000L * reconnectCount) // 阶梯式延迟：3s, 6s, 9s
                try {
                    _connectionState.value = P2pConnectionState.Connecting(WifiP2pDevice().apply { deviceAddress = config.deviceAddress })
                    p2pManager.connectSuspend(config)
                } catch (e: Exception) {
                    _connectionState.value = P2pConnectionState.Disconnected("自动重连第 ${reconnectCount} 次失败: ${e.message}")
                }
            }
        }
    }
}

四、高性能跨设备文件与文件夹流传输协议

为了全面支持包含 多级文件夹结构、大文件内容 的高性能互传，我们摒弃传统的单文件低效传输模式，制定了一套高度精简、紧凑的高性能流式二进制传输协议。传输分为两个阶段：元数据阶（Metadata Block） 与 原始二进制流数据阶（Payload Storage）。

4.1 二进制传输协议帧设计

每次传输开始时，发送端先向 TCP 通道下发一个固定长度或前置声明大小的 UTF-8 JSON 报文头（元数据），随后不间断直连下发文件体。结构体设计如下：

/**
 * 文件/文件夹传输统一元数据协议头
 */
data class TransferMetadata(
    val isFolder: Boolean,               // 是否是文件夹
    val relativePath: String,           // 相对根目录的路径 (例如: "Docs/Report.pdf" 或 "Images/")
    val totalFileSize: Long,            // 当前文件块的准确字节数 (文件夹则为 0)
    val fileIdentifier: String          // 由文件绝对路径加修改时间生成的 MD5 唯一戳，用于脏数据清理机制
)

4.2 实时流速与进度反馈模型

data class TransferProgress(
    val fileIdentifier: String,
    val relativePath: String,
    val bytesTransferred: Long,
    val totalBytes: Long,
    val progress: Float,                // 范围 0.0f ~ 100.0f
    val speedMbps: Double               // 实时传输速率 (Mbps)
)

4.3 核心发送端（Sender）协程化实现

import com.google.gson.Gson
import java.io.File
import java.io.FileInputStream
import java.io.OutputStream
import java.net.Socket
import kotlinx.coroutines.Dispatchers
import kotlinx.coroutines.flow.Flow
import kotlinx.coroutines.flow.flow
import kotlinx.coroutines.flow.flowOn
import kotlin.math.roundToInt

class P2pDataSender(private val targetIp: String, private val port: Int = 8899) {
    private val gson = Gson()

    /**
     * 发送单文件或递归发送文件夹的挂起函数
     * 通过 Flow 实时冷流向上层发射进度数据
     */
    fun sendPayload(inputFiles: List<File>): Flow<TransferProgress> = flow {
        val allFiles = mutableListOf<Pair<File, String>>()
        
        // 1. 预处理：扁平化递归扫描解析出所有的相对路径与绝对物理文件对应关系
        inputFiles.forEach { file ->
            if (file.isDirectory) {
                file.walkTopDown().filter { it.isFile }.forEach { subFile ->
                    val relative = file.parentFile?.let { subFile.relativeTo(it).path } ?: subFile.name
                    allFiles.add(subFile to relative.replace("\\", "/"))
                }
            } else {
                allFiles.add(file to file.name)
            }
        }

        // 2. 启动 Socket 穿透
        Socket(targetIp, port).use { socket ->
            socket.tcpNoDelay = true // 关闭 Nagle 算法，全面榨干带宽降低延迟
            val outputStream = socket.getOutputStream()
            val buffer = ByteArray(64 * 1024) // 64KB 高性能高吞吐缓冲区

            allFiles.forEach { (file, relativePath) ->
                val identifier = "${file.name}_${file.lastModified()}_${file.length()}"
                val metadata = TransferMetadata(
                    isFolder = false,
                    relativePath = relativePath,
                    totalFileSize = file.length(),
                    fileIdentifier = identifier
                )

                // A. 序列化并写出元数据头
                val metaJson = gson.toJson(metadata)
                val metaBytes = metaJson.toByteArray(Charsets.UTF_8)
                
                // 写入 4 字节的 Header 长度，解决粘包分包断包问题
                val lenBuffer = ByteArray(4)
                lenBuffer[0] = (metaBytes.size shr 24).toByte()
                lenBuffer[1] = (metaBytes.size shr 16).toByte()
                lenBuffer[2] = (metaBytes.size shr 8).toByte()
                lenBuffer[3] = (metaBytes.size).toByte()
                
                outputStream.write(lenBuffer)
                outputStream.write(metaBytes)
                outputStream.flush()

                // B. 流式循环写出文件 Payload 主体
                FileInputStream(file).use { fileInput ->
                    var totalRead: Long = 0
                    val fileLength = file.length()
                    var lastUpdateTime = System.currentTimeMillis()
                    var lastUpdatedBytes: Long = 0

                    var bytesRead = fileInput.read(buffer)
                    while (bytesRead != -1) {
                        outputStream.write(buffer, 0, bytesRead)
                        totalRead += bytesRead
                        
                        val currentTime = System.currentTimeMillis()
                        val timeDelta = currentTime - lastUpdateTime
                        
                        // 每 300ms 计算并向外发射一次高精度的速度与进度数据，避免频繁阻塞UI
                        if (timeDelta >= 300 || totalRead == fileLength) {
                            val bytesDelta = totalRead - lastUpdatedBytes
                            // 实时速率数学公式： Speed(Mbps) = (ΔBytes * 8) / (ΔTime(ms) / 1000) / 1,000,000
                            val speedMbps = if (timeDelta > 0) {
                                (bytesDelta * 8.0 / (timeDelta / 1000.0)) / (1024.0 * 1024.0)
                            } else 0.0
                            
                            val progressPercent = if (fileLength > 0) {
                                ((totalRead.toDouble() / fileLength.toDouble()) * 100.0).toFloat()
                            } else 100.0f

                            emit(TransferProgress(
                                fileIdentifier = identifier,
                                relativePath = relativePath,
                                bytesTransferred = totalRead,
                                totalBytes = fileLength,
                                progress = progressPercent,
                                speedMbps = speedMbps
                            ))
                            
                            lastUpdateTime = currentTime
                            lastUpdatedBytes = totalRead
                        }
                        bytesRead = fileInput.read(buffer)
                    }
                }
                outputStream.flush()
            }
        }
    }.flowOn(Dispatchers.IO)
}

五、严密的接收端崩溃健壮性与脏数据清理机制

在跨设备长连无线传输过程中，随时可能发生物理阻断、电量耗尽导致的应用 OOM 或者是系统主动杀死进程。此时，接收端的磁盘往往残留着大量的写到一半的损坏垃圾文件（脏数据）。框架引入了事务型影子文件（Shadow File）及强力清理机制。

5.1 影子文件事务协议设计

  1. 接收端接收到任何文件开始指令后，不在目标路径直接创建真实文件，而是创建扩展名为 .downloading_tmp 的临时影子文件。
  2. 接收端将当前正在执行的事务信息（包含唯一标识码符 fileIdentifier 和影子文件的全路径）实时持久化在内存的独立 Active 集合或本地 KV 库中。
  3. 一旦发生任何 IOException 异常，在对外抛出异常中断的同时，必须无条件触发影子文件擦除，精准实现文件系统回滚操作。
  4. 只有整个数据流完全接收、校验和闭合后，才会原子化地重命名为真实目标文件名，并从活跃事务中剔除。

5.2 核心接收端（Receiver）原子级安全实现

import com.google.gson.Gson
import java.io.File
import java.io.FileOutputStream
import java.io.InputStream
import java.net.ServerSocket
import java.net.Socket
import java.util.concurrent.ConcurrentHashMap
import kotlinx.coroutines.Dispatchers
import kotlinx.coroutines.withContext

class P2pDataReceiver(
    private val baseStorageDir: File,
    private val port: Int = 8899
) {
    private val gson = Gson()
    // 线程安全的全局活跃传输事务清单，防意外崩溃留脏
    private val activeTransactions = ConcurrentHashMap<String, File>()

    suspend fun startServerListening(onSuccess: (String) -> Unit) = withContext(Dispatchers.IO) {
        var serverSocket: ServerSocket? = null
        try {
            serverSocket = ServerSocket(port)
            while (true) {
                val clientSocket = serverSocket.accept()
                processClientConnection(clientSocket, onSuccess)
            }
        } finally {
            serverSocket?.close()
        }
    }

    private fun processClientConnection(socket: Socket, onSuccess: (String) -> Unit) {
        socket.use { client ->
            val inputStream = client.getInputStream()
            val lenBuffer = ByteArray(4)
            val buffer = ByteArray(64 * 1024)

            while (true) {
                // 1. 读取4字节头长度
                val readLenHead = readFully(inputStream, lenBuffer)
                if (readLenHead == -1) break // 远端全部发送完成，流正常终止

                val metaLength = ((lenBuffer[0].toInt() and 0xFF) shl 24) or
                                 ((lenBuffer[1].toInt() and 0xFF) shl 16) or
                                 ((lenBuffer[2].toInt() and 0xFF) shl 8) or
                                 (lenBuffer[3].toInt() and 0xFF)

                val metaBuffer = ByteArray(metaLength)
                readFully(inputStream, metaBuffer)
                
                val metadataJson = String(metaBuffer, Charsets.UTF_8)
                val metadata = gson.fromJson(metadataJson, TransferMetadata::class.java)

                // 2. 计算安全的目标存储路径与影子临时文件路径
                val targetFile = File(baseStorageDir, metadata.relativePath)
                targetFile.parentFile?.mkdirs() // 自动补全可能缺失的多级目录结构

                val shadowFile = File(targetFile.absolutePath + ".downloading_tmp")
                
                // 3. 将当前事务注册进内存防灾黑板
                activeTransactions[metadata.fileIdentifier] = shadowFile

                try {
                    // 4. 流式持久化落地影子文件
                    FileOutputStream(shadowFile).use { fos ->
                        var remaining = metadata.totalFileSize
                        while (remaining > 0) {
                            val readChunk = inputStream.read(buffer, 0, Math.min(buffer.size.toLong(), remaining).toInt())
                            if (readChunk == -1) {
                                throw java.io.IOException("Payload 传输意外中断，预设数据不齐！")
                            }
                            fos.write(buffer, 0, readChunk)
                            remaining -= readChunk
                        }
                        fos.flush()
                    }

                    // 5. 校验闭合，原子转移重命名
                    if (shadowFile.exists() && shadowFile.length() == metadata.totalFileSize) {
                        if (targetFile.exists()) targetFile.delete() // 覆盖旧同名文件
                        if (shadowFile.renameTo(targetFile)) {
                            // 移除事务追踪
                            activeTransactions.remove(metadata.fileIdentifier)
                            onSuccess(targetFile.absolutePath)
                        } else {
                            throw java.io.IOException("重命名影子文件失败：${targetFile.name}")
                        }
                    } else {
                        throw java.io.IOException("落盘数据长度不匹配，文件校验损坏。")
                    }

                } catch (e: Exception) {
                    // 🔴 触发脏数据强清理机制：对异常中断事务进行全自动垃圾无情擦除
                    performDirtyCleanup(metadata.fileIdentifier)
                    throw e // 将异常向上抛出以触发外部重连状态机
                }
            }
        }
    }

    /**
     * 单个活跃事务脏数据强制清理机制
     */
    fun performDirtyCleanup(fileIdentifier: String) {
        val brokenFile = activeTransactions.remove(fileIdentifier)
        if (brokenFile != null && brokenFile.exists()) {
            try {
                brokenFile.delete()
            } catch (ignored: Exception) {
                // 防止清理本身二次抛出干扰核心链路
            }
        }
    }

    /**
     * 全局兜底清理函数：供应用冷启动或 P2P 断连重置时强力洗盘，清除所有残留 .downloading_tmp 文件
     */
    fun performGlobalSanitize() {
        activeTransactions.clear()
        baseStorageDir.walkTopDown().filter { it.name.endsWith(".downloading_tmp") }.forEach { tmpFile ->
            try { tmpFile.delete() } catch (ignored: Exception) {}
        }
    }

    private fun readFully(inputStream: InputStream, targetBuffer: ByteArray): Int {
        var totalRead = 0
        while (totalRead < targetBuffer.size) {
            val bytesRead = inputStream.read(targetBuffer, totalRead, targetBuffer.size - totalRead)
            if (bytesRead == -1) {
                if (totalRead == 0) return -1
                else throw java.io.IOException("流在预定读取长度前意外干涸。")
            }
            totalRead += bytesRead
        }
        return totalRead
    }
}

六、工程化：解耦编译出 AAR 模块组件

为了使整个 Wi-Fi P2P 线性协程传输套件能够被其他项目组件独立开箱即用，必须将其抽离为独立的 Android Library 模块并输出 AAR 归档依赖包包。

6.1 子模块配置清单：build.gradle.kts

plugins {
    id("com.android.library")
    id("org.jetbrains.kotlin.android")
}

android {
    namespace = "com.leavesczy.wifip2p.core"
    compileSdk = 34

    defaultConfig {
        minSdk = 21
        testInstrumentationRunner = "androidx.test.runner.AndroidJUnitRunner"
        consumerProguardFiles("consumer-rules.pro") // 消费者混淆规约保护
    }

    buildTypes {
        release {
            isMinifyEnabled = false // 库内部不强制开启混淆，交由宿主App最终控制
            proguardFiles(getDefaultProguardFile("proguard-android-optimize.txt"), "proguard-rules.pro")
        }
    }
    compileOptions {
        sourceCompatibility = JavaVersion.VERSION_17
        targetCompatibility = JavaVersion.VERSION_17
    }
    kotlinOptions {
        jvmTarget = "17"
        freeCompilerArgs += listOf("-Xjvm-default=all") // 确保高阶兼容
    }
}

dependencies {
    // 仅依赖最基础的 Kotlin 核心库与协程库，确保库的高度轻量与纯净
    implementation("org.jetbrains.kotlinx:kotlinx-coroutines-core:1.7.3")
    implementation("org.jetbrains.kotlinx:kotlinx-coroutines-android:1.7.3")
    implementation("com.google.code.gson:gson:2.10.1")
}

6.2 自动化 AAR 编译与打包流水指令

在 Android Studio 底部的 Terminal 终端或 CI/CD 服务器上，定位到工程的根目录，键入以下专有 Gradle 包装器命令进行无痛工业化构建：

# 清理并针对单模块执行构建 release 版本的组件发布任务
./gradlew :wifip2p-core:clean :wifip2p-core:assembleRelease

构建成功后，输出的极简标准 .aar 归档依赖文件将存放于以下标准文件树目录树中：

[您的工程根目录]/wifip2p-core/build/outputs/aar/wifip2p-core-release.aar

6.3 AAR 混淆与规约控制：consumer-rules.pro

为了杜绝第三方集成后使用 R8/Proguard 进行激进的代码压缩与重命名导致二进制 Socket 解析元数据失败，必须在 AAR 内部固化混淆豁免规则：

# 保证核心跨端通信的元数据实体类不被混淆
-keep class com.leavesczy.wifip2p.core.TransferMetadata { *; }
-keep class com.leavesczy.wifip2p.core.TransferProgress { *; }

# 豁免协程底层状态模型
-keep class com.leavesczy.wifip2p.core.P2pConnectionState { *; }
